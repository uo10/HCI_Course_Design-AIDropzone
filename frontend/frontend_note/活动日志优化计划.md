# 活动日志优化计划（仅 R1）

> 读者：前端 · 约束：**只改前端展示**，不动后端、不新增 API

## 要完成什么

活动日志列表按时间 **最新在上、最旧在下**，与 Mock / 联调模式表现一致。

「撤回」仍走 `POST /undo`，本项不改。

## 现状（改之前）

- `GET /journal` 返回 **旧 → 新**（正常）。
- `useActivityLog.refresh()` 直接 `map`，联调时列表 **最旧在上**。
- Mock 的 `addEntry` 用 `[entry, ...prev]`，已是 **新在上** → 两种模式不一致。

## 怎么做

在 [`src/hooks/useActivityLog.ts`](../src/hooks/useActivityLog.ts) 增加 `sortNewestFirst`：

- 主键：`timestamp` 降序
- 同秒：`id` 降序

用于 `refresh()`、`loadMockEntries()`、`addEntry()`（Mock）。

## 验收

1. `electron:dev:full`：多次改名/导出后打开活动日志，**最新一条在最上**。
2. Mock 模式：新记录同样 **新在上**。
3. 「撤回」行为与改前一致。

## 不做

- 删除日志记录（R2 已砍掉）
- `POST /journal/delete` 及后端改动
