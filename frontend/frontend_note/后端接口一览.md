# AI Dropzone 后端接口一览（给前端）

本文档以当前代码 `backend/main.py` 与 `backend/models/*.py` 为准，整理后端实际可用接口。

- 服务基址（本地开发）：`http://127.0.0.1:8000`
- 当前版本：`1.0.0`（见 `FastAPI(title="AI Dropzone Backend", version="1.0.0")`）
- 当前实际接口：`/parse`、`/parse/batch`、`/rename`、`/undo`、`/export`

---

## 0. 通用字段与约束

### 0.1 `FileMetadata`（文件元信息）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | `string` | 是 | 文件绝对路径 |
| `size_bytes` | `int` | 是 | 文件大小（>=0） |
| `extension` | `string` | 是 | 扩展名（不带 `.`） |
| `mime_type` | `string` | 否 | 默认 `application/octet-stream` |
| `name_before_drop` | `string` | 是 | 原始文件名（含扩展名） |

### 0.2 `OperationStatus`

- `success`：成功
- `failure`：失败

### 0.3 `Tag` / `TagSet`

- 标签格式：`^[a-z0-9_]+$`
- 长度：1~64
- `TagSet` 在 JSON 中通常表现为字符串数组（模型内部是集合）

### 0.4 `NamingSchema`

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `pattern` | `string` | `{tag}_{date}_{name}.{ext}` | 命名模板 |
| `separator` | `string` | `_` | 片段分隔符 |
| `case` | `string` | `lower` | `lower` / `upper` / `preserve` |

### 0.5 `RenameMode`

- `skip`：重名就跳过
- `overwrite`：重名就覆盖
- `auto_increment`：重名就自动加后缀

## 1. 接口：单文件解析

### 1) 名字

- `POST /parse`

### 2) 简单功能

- 输入一个文件元信息，后端返回 AI 解析结果（建议文件名、分类、标签、摘要、置信度）。

### 3) 输入表单 / 返回表单

#### 输入（`ParseRequest`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | `FileMetadata` | 是 | 要解析的文件 |
| `context_tags` | `string[]` | 否 | 前端已有标签上下文 |
| `prefer_mock` | `bool` | 否 | 是否强制走 Mock 解析 |

示例：

```json
{
  "file": {
    "path": "C:\\Users\\demo\\Desktop\\a.png",
    "size_bytes": 123456,
    "extension": "png",
    "mime_type": "image/png",
    "name_before_drop": "a.png"
  },
  "context_tags": ["work"],
  "prefer_mock": false
}
```

#### 返回（`ParseResult`）

成功示例：

```json
{
  "status": "success",
  "data": {
    "file_path": "C:\\Users\\demo\\Desktop\\a.png",
    "suggested_name": "image_20260602_a.png",
    "category": "image",
    "tags": ["image", "media"],
    "summary": "A raster or vector image file.",
    "keywords": ["screenshot"],
    "confidence": 0.85,
    "parsed_at": "2026-06-02T10:00:00.000000"
  },
  "error": null
}
```

失败示例：

```json
{
  "status": "failure",
  "data": null,
  "error": "Unsupported file extension: .xyz"
}
```

## 2. 接口：批量解析

### 1) 名字

- `POST /parse/batch`

### 2) 简单功能

- 一次提交多个文件，后端逐个解析并返回成功列表与失败列表。

### 3) 输入表单 / 返回表单

#### 输入（`BatchParseRequest`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `files` | `FileMetadata[]` | 是 | 文件数组（1~200） |
| `context_tags` | `string[]` | 否 | 上下文标签 |
| `prefer_mock` | `bool` | 否 | 是否强制 Mock |

示例：

```json
{
  "files": [
    {
      "path": "C:\\Users\\demo\\Desktop\\a.jpg",
      "size_bytes": 8888,
      "extension": "jpg",
      "mime_type": "image/jpeg",
      "name_before_drop": "a.jpg"
    }
  ],
  "context_tags": null,
  "prefer_mock": false
}
```

#### 返回（`BatchParseResult`）

```json
{
  "status": "success",
  "items": [
    {
      "file_path": "C:\\Users\\demo\\Desktop\\a.jpg",
      "suggested_name": "image_a.jpg",
      "category": "image",
      "tags": ["image"],
      "summary": "A raster or vector image file.",
      "keywords": [],
      "confidence": 0.85,
      "parsed_at": "2026-06-02T10:00:00.000000"
    }
  ],
  "errors": []
}
```

## 3. 接口：文件重命名

### 1) 名字

- `POST /rename`

### 2) 简单功能

- 根据前端确认结果执行批量重命名；支持仅预览（`dry_run=true`）不落盘。

### 3) 输入表单 / 返回表单

#### 输入（`RenameRequest`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `items` | `RenameItem[]` | 是 | 重命名列表（1~500） |
| `naming` | `NamingSchema` | 否 | 命名规则 |
| `dry_run` | `bool` | 否 | `true` 仅预览 |
| `conflict_mode` | `RenameMode` | 否 | 重名处理策略 |

`RenameItem`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `source_path` | `string` | 是 | 原路径 |
| `new_name` | `string` | 是 | 新文件名（不含目录） |
| `tags_applied` | `string[]` | 否 | 已确认标签 |
| `notes` | `string` | 否 | 备注 |

示例：

```json
{
  "items": [
    {
      "source_path": "C:\\Users\\demo\\Desktop\\a.png",
      "new_name": "design_a.png",
      "tags_applied": ["design"],
      "notes": ""
    }
  ],
  "naming": {
    "pattern": "{tag}_{date}_{name}.{ext}",
    "separator": "_",
    "case": "lower"
  },
  "dry_run": false,
  "conflict_mode": "auto_increment"
}
```

#### 返回（`RenameResult`）

```json
{
  "status": "success",
  "dry_run": false,
  "renamed": [
    {
      "old": "C:\\Users\\demo\\Desktop\\a.png",
      "new": "C:\\Users\\demo\\Desktop\\design_a.png",
      "tags": ["design"]
    }
  ],
  "skipped": [],
  "errors": [],
  "timestamp": "2026-06-02T10:00:01.000000"
}
```

## 4. 接口：撤销操作

### 1) 名字

- `POST /undo`

### 2) 简单功能

- 按回滚日志撤销最近 N 条操作，可按操作类型过滤（如只撤销 rename）。

### 3) 输入表单 / 返回表单

#### 输入（`UndoRequest`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `count` | `int` | 否 | 撤销条数，默认 1，范围 1~100 |
| `filter_operation` | `string` | 否 | `rename` / `export` / `delete` |

示例：

```json
{
  "count": 1,
  "filter_operation": "rename"
}
```

#### 返回（`UndoResult`）

```json
{
  "status": "success",
  "undone": [
    {
      "entry_id": 5,
      "operation": "rename",
      "timestamp": "2026-06-02T10:00:01.000000",
      "original_path": "C:\\Users\\demo\\Desktop\\a.png",
      "new_path": "C:\\Users\\demo\\Desktop\\design_a.png",
      "tags_snapshot": ["design"],
      "metadata": {}
    }
  ],
  "failed": [],
  "remaining_log_size": 3
}
```

## 5. 接口：按标签导出压缩包

### 1) 名字

- `POST /export`

### 2) 简单功能

- 从 workspace 中筛选“同时包含指定标签”的文件，导出为 zip，并可附带 `manifest.json`。

### 3) 输入表单 / 返回表单

#### 输入（`ExportRequest`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `tags` | `string[]` | 是 | 标签集合，至少 1 个（AND 语义） |
| `output_dir` | `string` | 是 | 输出目录 |
| `package_name` | `string` | 否 | zip 名（默认 `export`） |
| `include_manifest` | `bool` | 否 | 是否写入 manifest |

示例：

```json
{
  "tags": ["document", "report"],
  "output_dir": "C:\\Users\\demo\\Desktop\\exports",
  "package_name": "q1_reports",
  "include_manifest": true
}
```

#### 返回（`ExportResult`）

```json
{
  "status": "success",
  "zip_path": "C:\\Users\\demo\\Desktop\\exports\\q1_reports.zip",
  "manifest": {
    "created_at": "2026-06-02T10:00:02.000000",
    "tag_filter": ["document", "report"],
    "total_files": 2,
    "total_size_bytes": 1048576,
    "entries": []
  },
  "errors": []
}
```

## 6. 当前版本接口覆盖提醒

当前这版后端未暴露以下接口（调用会 404）：

- `GET /config`
- `PUT /config`
- `GET /journal`

前端如果需要这些能力，请先和后端确认分支/版本是否一致。
