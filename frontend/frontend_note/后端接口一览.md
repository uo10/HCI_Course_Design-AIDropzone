# AI Dropzone 后端接口一览（给前端）

本文档以当前代码 `backend/main.py` 与 `backend/models/*.py` 为准，整理后端实际可用接口。

- 服务基址（本地开发）：`http://127.0.0.1:8000`
- 当前版本：`1.0.0`
- 文档更新：命名重生成（`POST /parse/regenerate`、`config.naming_style_prompt`）+ `/config`、`/journal` 等

## 接口总览

| 方法 | 路径 | 前端常用场景 |
|------|------|----------------|
| `POST` | `/parse` | 拖入单文件 → AI 解析（自动应用 config 中的命名风格） |
| `POST` | `/parse/regenerate` | 详情页「重新生成」→ 只更新建议名，不改盘 |
| `POST` | `/parse/batch` | 批量解析 |
| `POST` | `/rename` | 确认改名（含 `dry_run` 预览） |
| `POST` | `/undo` | 撤销；支持 `entry_ids` 按 ID 精确撤销 |
| `POST` | `/export` | 按标签打包 zip |
| `GET` | `/config` | 设置页初始化（Key 已脱敏） |
| `PUT` | `/config` | 保存设置（只传改动的字段） |
| `GET` | `/journal` | 活动日志页数据源 |
| `DELETE` | `/journal` | 仅删除日志记录（不撤回文件） |
| `GET` | `/settings/workspace` | 查询整理篮路径 |
| `POST` | `/settings/workspace` | 单独修改整理篮路径 |
| `GET` | `/tags` | 标签库（含各标签文件数） |
| `POST` | `/tags/rescan` | 重建 workspace 标签索引 |
| `GET` | `/settings/llm` | 查询 LLM 配置（Key 脱敏） |
| `POST` | `/settings/llm` | 单独更新 LLM 配置 |

> 设置页优先用 **`GET/PUT /config`**；`/settings/*` 为更细粒度的备用接口。

## 0. 通用字段与约束

### 0.1 `FileMetadata`（文件元信息）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | `string` | 是 | 文件绝对路径 |
| `size_bytes` | `int` | 是 | 文件大小（>=0） |
| `extension` | `string` | 是 | 扩展名（不带 `.`） |
| `mime_type` | `string` | 否 | 默认 `application/octet-stream` |
| `name_before_drop` | `string` | 是 | 原始文件名（含扩展名） |

### 0.2 `OperationStatus`

- `success`：成功
- `failure`：失败

### 0.3 `Tag` / `TagSet`

- 标签格式：允许中英文、数字、下划线等；**禁止**空白及 `<>:"/\|?*` 等文件系统非法字符（与 `backend/models/common.py` 一致）
- 长度：1~64
- `TagSet` 在 JSON 中通常表现为字符串数组（模型内部是集合）

### 0.4 `NamingSchema`

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `pattern` | `string` | `{tag}_{date}_{name}.{ext}` | 命名模板 |
| `separator` | `string` | `_` | 片段分隔符 |
| `case` | `string` | `lower` | `lower` / `upper` / `preserve` |

### 0.5 `RenameMode`

- `skip`：重名就跳过
- `overwrite`：重名就覆盖
- `auto_increment`：重名就自动加后缀

## 1. 接口：单文件解析

### 1) 名字

- `POST /parse`

### 2) 简单功能

- 输入一个文件元信息，后端返回 AI 解析结果（建议文件名、分类、标签、摘要、置信度）。已配置 LLM 时优先走真模型，失败可回退 Mock。
- **自动应用** `config.json` 中的 `naming_style_prompt`；请求体**无需**传风格字段。

### 3) 输入表单 / 返回表单

#### 输入（`ParseRequest`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | `FileMetadata` | 是 | 要解析的文件 |
| `context_tags` | `string[]` | 否 | 前端已有标签上下文 |
| `prefer_mock` | `bool` | 否 | 是否强制走 Mock 解析 |

示例：

```json
{
  "file": {
    "path": "C:\\Users\\demo\\Desktop\\a.png",
    "size_bytes": 123456,
    "extension": "png",
    "mime_type": "image/png",
    "name_before_drop": "a.png"
  },
  "context_tags": ["work"],
  "prefer_mock": false
}
```

#### 返回（`ParseResult`）

成功示例：

```json
{
  "status": "success",
  "data": {
    "file_path": "C:\\Users\\demo\\Desktop\\a.png",
    "suggested_name": "image_20260602_a.png",
    "category": "image",
    "tags": ["image", "media"],
    "summary": "A raster or vector image file.",
    "keywords": ["screenshot"],
    "confidence": 0.85,
    "parsed_at": "2026-06-02T10:00:00.000000"
  },
  "error": null
}
```

失败示例：

```json
{
  "status": "failure",
  "data": null,
  "error": "Unsupported file extension: .xyz"
}
```

## 1b. 接口：重生成解析（不改盘）

### 1) 名字

- `POST /parse/regenerate`

### 2) 简单功能

- 对已有文件重新计算建议名/标签/摘要；合并 **config 中的 `naming_style_prompt`** 与请求体中的 **`extra_prompt`**（单次补充）。**不调用 `/rename`，不触碰磁盘。**

### 3) 输入表单 / 返回表单

#### 输入（`RegenerateRequest`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | `FileMetadata` | 是 | 与 `/parse` 相同 |
| `extra_prompt` | `string` | 否 | 单次命名要求，默认 `""` |
| `context_tags` | `string[]` | 否 | 详情页用户已确认的标签（模型侧预留） |
| `prefer_mock` | `bool` | 否 | 强制 Mock |

示例：

```json
{
  "file": {
    "path": "C:\\Users\\demo\\Desktop\\report.pdf",
    "size_bytes": 204800,
    "extension": "pdf",
    "mime_type": "application/pdf",
    "name_before_drop": "report.pdf"
  },
  "extra_prompt": "强调算法名，保留 v2 版本号",
  "context_tags": ["document", "coursework"]
}
```

#### 返回

- 与 `POST /parse` 相同：`ParseResult`（`status` + `data` / `error`）。

---

## 2. 接口：批量解析

### 1) 名字

- `POST /parse/batch`

### 2) 简单功能

- 一次提交多个文件，后端逐个解析并返回成功列表与失败列表。

### 3) 输入表单 / 返回表单

#### 输入（`BatchParseRequest`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `files` | `FileMetadata[]` | 是 | 文件数组（1~200） |
| `context_tags` | `string[]` | 否 | 上下文标签 |
| `prefer_mock` | `bool` | 否 | 是否强制 Mock |

#### 返回（`BatchParseResult`）

```json
{
  "status": "success",
  "items": [ { "...ParseItem 字段同单文件..." } ],
  "errors": [ { "path": "...", "error": "..." } ]
}
```

## 3. 接口：文件重命名

### 1) 名字

- `POST /rename`

### 2) 简单功能

- 根据前端确认结果执行批量重命名；`dry_run=true` 时仅预览不写盘。

### 3) 输入表单 / 返回表单

#### 输入（`RenameRequest`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `items` | `RenameItem[]` | 是 | 重命名列表（1~500） |
| `naming` | `NamingSchema` | 否 | 命名规则 |
| `dry_run` | `bool` | 否 | `true` 仅预览 |
| `conflict_mode` | `RenameMode` | 否 | 重名处理策略 |

`RenameItem`：`source_path`、`new_name`、`tags_applied`、`notes`

#### 返回（`RenameResult`）

```json
{
  "status": "success",
  "dry_run": false,
  "renamed": [ { "old": "...", "new": "...", "tags": ["design"] } ],
  "skipped": [],
  "errors": [],
  "timestamp": "2026-06-02T10:00:01.000000"
}
```

## 4. 接口：撤销操作

### 1) 名字

- `POST /undo`

### 2) 简单功能

- 撤销回滚日志中的操作。可按最近 N 条撤销，也可用 **`entry_ids` 精确撤销某几条**（前端活动日志常用后者）。

### 3) 输入表单 / 返回表单

#### 输入（`UndoRequest`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `count` | `int` | 否 | 撤销最近 N 条，默认 1，范围 1~100；**若传了 `entry_ids` 则忽略** |
| `filter_operation` | `string` | 否 | `rename` / `export` / `delete` |
| `entry_ids` | `int[]` | 否 | 指定日志 `entry_id` 列表，优先于 `count` |

按条数撤销示例：

```json
{
  "count": 1,
  "filter_operation": "rename"
}
```

按 ID 精确撤销示例（前端 `undo({ entry_ids: [5] })`）：

```json
{
  "entry_ids": [5]
}
```

#### 返回（`UndoResult`）

```json
{
  "status": "success",
  "undone": [
    {
      "entry_id": 5,
      "operation": "rename",
      "timestamp": "2026-06-02T10:00:01.000000",
      "original_path": "C:\\Users\\demo\\Desktop\\a.png",
      "new_path": "C:\\Users\\demo\\Desktop\\design_a.png",
      "tags_snapshot": ["design"],
      "metadata": {}
    }
  ],
  "failed": [],
  "remaining_log_size": 3
}
```

## 5. 接口：按标签导出压缩包

### 1) 名字

- `POST /export`

### 2) 简单功能

- 从 **workspace 整理篮** 中筛选“同时包含指定标签”的文件，导出为 zip，并可附带 `manifest.json`。

### 3) 输入表单 / 返回表单

#### 输入（`ExportRequest`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `tags` | `string[]` | 是 | 标签集合，至少 1 个（AND 语义） |
| `output_dir` | `string` | 是 | 输出目录 |
| `package_name` | `string` | 否 | zip 名（默认 `export`） |
| `include_manifest` | `bool` | 否 | 是否写入 manifest |

#### 返回（`ExportResult`）

```json
{
  "status": "success",
  "zip_path": "C:\\Users\\demo\\Desktop\\exports\\q1_reports.zip",
  "manifest": { "total_files": 2, "entries": [], "...": "..." },
  "errors": []
}
```

## 6. 接口：读取完整配置

### 1) 名字

- `GET /config`

### 2) 简单功能

- 设置页打开时拉取后端当前配置；LLM API Key **已脱敏**，用 `api_key_set` 判断是否已配置密钥。

### 3) 输入表单 / 返回表单

#### 输入

- 无请求体。

#### 返回

```json
{
  "config": {
    "workspace_root": "D:\\...\\backend\\workspace",
    "ai_parser": "mock",
    "naming_style_prompt": "偏学术、保留英文缩写、文件名不超过 25 字符",
    "ai_parser_options": {
      "llm": {
        "provider": "deepseek",
        "model": "deepseek-chat",
        "base_url": "",
        "api_key_set": true,
        "api_key": "sk-1***abcd"
      }
    }
  }
}
```

异常时可能带 `"error"` 且 `"config": null`。

## 7. 接口：保存配置

### 1) 名字

- `PUT /config`

### 2) 简单功能

- 批量更新 `config.json`；**只传需要改的字段**，未传的字段保持不变。

### 3) 输入表单 / 返回表单

#### 输入（字段均可选）

| 字段 | 类型 | 说明 |
|---|---|---|
| `workspace_root` | `string` | 整理篮路径 |
| `naming_style_prompt` | `string` | 命名风格常驻提示词；传 `""` 可清空 |
| `ai_parser` | `string` | `mock` 或 `llm` |
| `llm_provider` | `string` | 提供商 |
| `llm_model` | `string` | 模型名 |
| `llm_base_url` | `string` | API 基址 |
| `llm_api_key` | `string` | 明文密钥（写入 config） |

示例：

```json
{
  "workspace_root": "D:\\HCI_teamwork\\HCI_Course_Design-AIDropzone\\backend\\workspace",
  "ai_parser": "llm",
  "llm_api_key": "sk-..."
}
```

#### 返回

- 结构与 `GET /config` 相同，返回更新后的 `config` 对象。

---

## 8. 接口：操作日志（回滚日志）

### 1) 名字

- `GET /journal`

### 2) 简单功能

- 返回完整回滚日志数组，供前端「活动记录」列表展示；每条含 `entry_id`，撤销时传给 `POST /undo` 的 `entry_ids`。

### 3) 输入表单 / 返回表单

#### 输入

- 无请求体。

#### 返回

- `RollbackEntry[]`（JSON 数组），单条字段示例：

```json
[
  {
    "entry_id": 5,
    "operation": "rename",
    "timestamp": "2026-06-02T10:00:01.000000",
    "original_path": "C:\\Users\\demo\\Desktop\\a.png",
    "new_path": "C:\\Users\\demo\\Desktop\\design_a.png",
    "tags_snapshot": ["design"],
    "metadata": {}
  }
]
```

---

## 8b. 接口：删除日志记录（不撤回）

### 1) 名字

- `DELETE /journal`

### 2) 简单功能

- 按 `entry_id` 从 `rollback_log.json` 移除记录；**不**执行 rename/export 回滚，磁盘文件保持现状。

### 3) 输入表单 / 返回表单

#### 输入

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `entry_ids` | `int[]` | 是 | 要删除的日志 `entry_id` 列表 |

示例：

```json
{
  "entry_ids": [5, 7]
}
```

#### 返回

```json
{
  "status": "success",
  "deleted_count": 2,
  "requested_ids": [5, 7]
}
```

失败示例：`{"status": "failure", "error": "No entry_ids provided"}`

> 与 `POST /undo` 区别：撤回会恢复文件/删除导出 zip；删除仅清理日志。

## 9. 接口：整理篮路径（细分）

### `GET /settings/workspace`

- 查询当前 workspace 绝对路径及目录是否存在。

```json
{
  "status": "success",
  "workspace_root": "D:\\...\\workspace",
  "exists": true
}
```

### `POST /settings/workspace`

#### 输入（`WorkspaceUpdateRequest`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `new_path` | `string` | 是 | 新的整理篮路径 |

#### 返回（`WorkspaceUpdateResponse`）

- `status`、`workspace_root`、`message`

---

## 10. 接口：标签库

### `GET /tags`

- 返回 workspace 内标签及每个标签关联文件数；请求前会自动 rescan 未索引文件。

```json
{
  "status": "success",
  "workspace_root": "...",
  "total_files": 12,
  "tags": { "document": 3, "image": 5 }
}
```

### `POST /tags/rescan`

- 无请求体；强制重建标签索引。

```json
{
  "status": "success",
  "newly_indexed": 2,
  "total_files": 12
}
```

---

## 11. 接口：LLM 配置（细分）

### `GET /settings/llm`

- 返回 provider、model、脱敏后的 `api_key_masked` 等。

### `POST /settings/llm`

- Body 为字典，可传 `provider`、`model`、`api_key`、`api_key_env`、`timeout_seconds`、`max_retries` 等，只更新提供的字段。

> 与 `PUT /config` 功能重叠；前端设置页已统一走 `/config` 时，可不直接调用这两支。

---

## 12. 业务流程简图

```
GET/PUT /config（含 naming_style_prompt）
    ↓
拖入文件 → POST /parse（自动带命名风格）
    ↓
不满意 → POST /parse/regenerate（extra_prompt）→ 仅更新 UI 建议
    ↓
用户编辑名称/标签 → POST /rename（dry_run 可选）
    ↓
GET /journal 展示历史；POST /undo（count 或 entry_ids）撤销
    ↓
POST /export 按标签打包
    ↓
GET/PUT /config 维护 workspace、命名风格与 LLM 设置
```
